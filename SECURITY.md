# Безопасность и приватность

## Границы проекта

Используй только свою колонку или устройство, которым тебе разрешено управлять.
Проект не предоставляет root, firmware, обход входа или доступ к чужому аккаунту.
Установщик рассчитан на уже подготовленную ARM64/SysV-колонку с совпадающими
путями и отдельный сервер. Это не универсальный прошивальщик.

**Проект экспериментальный.** После последних исправлений речевого протокола
физическая голосовая приёмка и установка всего контура с пустого сервера на
реальную колонку ещё не подтверждены. Автотесты, HTTP health, ответ API и
наличие таймера возврата не гарантируют восстановление любого оборудования.
Нужны физический доступ, рабочий SSH и проверенный recovery своей firmware.

## Какие данные куда идут

- Микрофон → распознавание речи в Яндексе → мост на колонке.
- Бытовые команды остаются в штатном Яндексе. Для ИИ-вопроса распознанный
  текст и краткий контекст из RAM идут в **OmniRoute → подключённый CLI / OAuth-провайдер Gemini**.
- Ответ Gemini возвращается мосту и передаётся в Яндекс для родной озвучки
  (`nativeTtsGenerate`); аудио воспроизводится колонкой.

Это не офлайн-режим. Распознавание, синтез и обработка текста зависят от
внешних сервисов и их условий. Предупреди собеседников о такой обработке и
получи необходимое согласие. Не отправляй чувствительные сведения без права
на их передачу Яндексу, Google и владельцу сервера OmniRoute.

В публичном примере выключены conversation log, Home Assistant, MCP и
assistant tools. Краткий диалог хранится в RAM и очищается по TTL/перезапуску.
Ограниченный ключ OmniRoute создаётся с `noLog`, но это **не гарантия отсутствия
любых журналов**: системные логи, резервные копии и политика провайдера
контролируются отдельно. Кеш `thinking.ogg` предназначен только для фиксированной
фразы «Думаю», создаётся локально и в Git не входит.

## Сеть и доступ

- Мост слушает только `127.0.0.1:18861` на колонке. Не открывай этот listener
  в LAN или интернет: через протокол проходят трафик и авторизация устройства.
- Новый OmniRoute привязывается к loopback и конкретному частному IPv4 сервера,
  по умолчанию порт `20128`. `0.0.0.0`, публичный bind и имя хоста мастер
  не принимает. Loopback сервера недоступен колонке как её локальный адрес.
- По умолчанию серверный участок использует **HTTP без TLS**. Это допустимо
  только в доверенной изолированной LAN или внутри защищённого VPN-маршрута.
  В общей/недоверенной сети ключ и текст могут быть перехвачены. Частный IP
  сам по себе не шифрует трафик.
- Управляющий интерфейс OmniRoute доступен на том же порту, поэтому закрывай
  сервер от лишних клиентов средствами своей сети и проверяй фактические
  Docker-публикации. Обязательная аутентификация не заменяет сетевую изоляцию.
- Мастер не создаёт публичный порт, DNS, HTTPS-прокси или туннель и не
  ослабляет firewall ради подключения. Docker может управлять собственными
  правилами публикации портов; владелец обязан проверить доступность снаружи.
- Для другой сети нужен отдельно настроенный HTTPS с проверкой сертификата
  либо защищённый маршрут от самой колонки/её роутера. VPN только на ноутбуке
  не решает доступ устройства к серверу. Не выключай TLS-проверку и не делай
  новый публичный вход ради переезда в офис.

SSH работает по заранее разрешённому ключу, с `BatchMode=yes` и
`StrictHostKeyChecking=yes`. При запуске с `sudo` ключ и known_hosts должны
быть доступны **root на сервере**. `ssh-keyscan` даёт только кандидата:
отпечаток нужно сверить по доверенному каналу до первого подключения.
Нельзя обходить несовпадение ключа хоста или использовать чужой SSH config.

## Разделение ключей и закрытые файлы

Новый `server/all` скачивает последний stable **оригинального OmniRoute**, проверяет
версию внутри образа и поднимает отдельный Compose-проект с собственным томом
и неизменяемым `image@sha256`. Точный релиз, commit и digest сохраняются в
`stack.json`, а не закрепляются старой константой в коде. Не заменяй digest на
плавающий `latest` и не обновляй работающий stack без копии и проверок. Создаются случайные
JWT/API/encryption secrets, обязательная API-аутентификация и пароль
администратора от 16 знаков. Установщик не передаёт контейнеру Docker socket
и не требует privileged-режима.

| Секрет | Где остаётся | Для чего |
| --- | --- | --- |
| Сессия CLI / OAuth Google или токен | Данные OmniRoute на сервере | Доступ к Gemini через CLI-сессию; на колонку не отправляется |
| Пароль администратора, JWT/API/encryption secrets | Серверный `gateway.env` и состояние шлюза | Управление и защита серверного состояния |
| Ограниченный ключ OmniRoute | Серверный `station.json`, на колонке `runtime.env` | Только генерация через выбранное владельцем комбо |
| Исходный firmware-конфиг | Закрытый резерв на сервере и `original.cfg` на колонке | Точное восстановление; может содержать данные аккаунта |

Владелец создаёт ключ колонки в UI оригинального OmniRoute с `scopes=[inference]`, `allowedCombos=[имя своего комбо]`,
`allowedModels=[]`, ограниченным режимом доступа и `noLog`. Он не должен иметь
admin/manage-права, разрешение прямых моделей или другие combo. Мастер
при `configure` проверяет отказ анонимному запросу, отказ управлению и отказ
тестовому прямому запросу модели. Успех генерации обязателен. Эти пробы не заменяют
проверку всех разрешений в UI и не доказывают запрет всех возможных моделей;
обычный `check` не повторяет отдельную пробу прямой модели.

Доступ к Gemini настраивается владельцем через CLI / Google OAuth в интерфейсе
OmniRoute; ключ Google AI Studio не требуется. Ограничения аккаунта, региональная
доступность и условия провайдера сохраняются. Сторонний OAuth-доступ может
ограничиваться условиями конкретного продукта — проверь их до подключения.
Авторизационные данные шлюза остаются на сервере; обращения к Google не становятся офлайн-режимом.

Серверный каталог `/opt/alice-gemini` и каталог колонки
`/data/opt/quasar-bridge` должны быть root-owned/`0700`; секретные файлы —
root-owned/`0600`. Ограничь также доступ к Docker и его томам: root и
пользователь с правами Docker могут читать эти данные. Не складывай состояние
в общий каталог или Git, даже приватный.

`runtime.env` — **исполняемый shell-файл**, не произвольный dotenv. Его
загружает `start.sh`. Не принимай чужие env-файлы, config, архивы и скрипты
как доверенные данные. Не выводи значения и хеши секретов в логи, Issue или
скриншоты; проверяй совпадение локально без публикации. Не отправляй
`station.json`, `gateway.env`, `runtime.env`, полный `quasar.cfg`, токены,
session IDs, serial/MAC, адреса своей сети, captures, аудиозаписи и полный syslog.

## Установка и возврат без перезаписи firmware

Quasar Bridge скачивается **из оригинального репозитория**, затем применяется
отдельный интеграционный патч. GitHub release разрешается в точный commit;
на скачанном исходнике выполняются race/vet, проверка конфига и маршрутов.
В `upstream.json` сохраняются commit, SHA-256 патча и проверенного исходника.
Проверка патча или тестов не прошла — запись на колонку не начинается.
Старой встроенной копии и обхода проверки нет. Ошибка загрузки также означает остановку.

Установка исполняет код, скачанный у оригинальных авторов, и применённый патч:
доверие к upstream остаётся обязательным. Commit/digest подтверждают идентичность,
но не отсутствие уязвимостей. Репозиторий не содержит замороженных исходников
сервисов в текущем дереве; прежняя история Git не переписана.

До изменений проверь, что SSH и физическое восстановление реально работают.
Прочитай скачанный исходник до запуска `sudo sh ./install.sh`; не передавай
непрочитанный удалённый скрипт прямо в root-shell.

Установщик отказывается при существующем состоянии, своём старом резерве,
занятом hook или чужом mount. Это предохранитель, не помеха, которую нужно
обойти удалением каталога. До hook выполняются проверки конфига/backend на
самой колонке и обратная сверка переданного комплекта. Оригинальный конфиг
сохраняется закрыто; в копии меняются только `uniProxyUrl` и `uniProxyQuicUrl`.
Stock `quasar.cfg`, `launch.json` и `S99quasar` не переписываются. Новый
`S98quasarbridge` устанавливается атомарно, исходный режим rootfs восстанавливается.

`all` **не перезагружает колонку сам**. После контролируемого reboot первый
запуск hook с `acceptance.pending` включает независимый 10-минутный таймер.
Без голосовой проверки не запускай `confirm`; `confirm --yes` запрещён.
При отсутствии подтверждения таймер ставит `disabled`, снимает только свой
точно записанный bind, сравнивает оригинал и перезагружает устройство на
штатный маршрут. Это защита первой установки, не голосовая пасхалка и не
универсальный watchdog от всех зависаний.

При неизвестном/двойном mount или изменённом конфиге скрипты отказывают;
при отказе таймера нужен локальный оператор, а не небезопасное размонтирование.
Не используй `umount -f`, запись stock-файла поверх чужого mount и массовый kill.
Ручной `rollback --target speaker` также отключает мост и проверяет оригинал,
но **после успеха нужен контролируемый reboot** из-за кеша endpoint в процессе.
Не удаляй комплект, hook или ключ до проверки штатной Алисы голосом.

Серверный `rollback --target server` останавливает только принадлежащий
установке Compose-проект, оставляя том и закрытое состояние. При сбое
серверной установки предпринимается такая же ограниченная остановка.
Чужие проекты не затрагиваются. Удаление данных/переустановка — отдельное
решение после проверки, не автоматическое продолжение мастера.

## Резервные копии, публикация и сообщения об ошибках

Для восстановления нужны **данные тома вместе с `gateway.env`, `station.json`
и остальным состоянием установки**. Копируй данные согласованно, без записи
в БД; храни архивы вне Git с закрытыми правами и шифрованием при переносе.
Ограниченный ключ сам по себе не заменяет encryption secret шлюза.
Восстановление не должно перезаписывать существующие каталог, том или stack.
Команды и условия — в [INSTALL.md](docs/INSTALL.md#9-закрытая-резервная-копия-и-восстановление-сервера).
Сам факт создания архива не подтверждает возможность восстановления:
испытай его отдельно на пустом сервере.

`scripts/check-public-tree.py` проверяет известные признаки в **Git index**,
но не заменяет просмотр рабочего diff и истории перед публикацией. Не считай
его успех доказательством отсутствия секретов в неиндексированных файлах.

При раскрытии ключа сначала отзови/замени его у владельца соответствующего
сервиса. Раскрытие серверного архива может затронуть не только ключ колонки,
но и сессию CLI Google в OmniRoute, пароль/секреты шлюза и данные устройства; объём ротации
определи по реально раскрытым файлам. Удаление секрета из последнего commit
не удаляет его из Git history и чужих копий.

В Issue или pull request передавай только очищенное описание: commit,
модель/firmware, этап и последовательность событий без личных данных.
Приватного адреса для приёма секретных отчётов этот репозиторий пока не
предоставляет — не отправляй действующие credentials публично.
